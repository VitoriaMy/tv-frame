# ESP32 伺服定位与同步滑盖版本说明

## 1. 文档目标

本文档用于细化 ESP32 作为主控时的系统架构、控制逻辑、状态机设计、输入输出接口建议、参数组织方式、软件保护策略以及后续扩展方向，便于将当前项目从概念控制方案逐步推进到可实现、可调试、可维护的软件架构。

---

## 2. 版本定位

本版本适用于以下需求：
- 主平台精准定位
- 前滑盖与平台同步联动
- 蓝牙监听作为启动条件
- 后续支持 Wi‑Fi、手动控制、状态显示与错误处理扩展

### 2.1 适用控制目标
- 设备开机后自动滑出到固定工作位
- 设备关机后自动回零并关闭上盖
- 支持平台回零、动作超时保护和异常停机
- 支持调试阶段的手动模式与参数调整

### 2.2 版本边界
本版本重点是 **ESP32 主控逻辑与控制架构**，默认：
- 主平台使用闭环驱动、伺服驱动或带编码器电机控制
- 前滑盖主要通过机械联动实现同步运动
- ESP32 负责系统判断、状态切换、动作下发和异常处理

---

## 3. 控制架构建议

建议采用以下控制分层：

1. **输入层**
   - 蓝牙状态
   - 原点开关
   - 终点保护开关
   - 手动按键（预留）
   - 急停输入（预留）

2. **逻辑层**
   - 状态机控制
   - 动作条件判断
   - 故障保护逻辑
   - 超时处理逻辑
   - 去抖与稳定延时逻辑

3. **执行层**
   - 驱动器控制
   - 位置目标下发
   - 停止与错误处理
   - 指示灯、蜂鸣器输出

4. **反馈层**
   - 当前位置
   - 到位状态
   - 故障状态
   - 调试输出
   - 运行日志

### 3.1 推荐软件模块划分
建议将程序划分为以下软件模块：

- `bluetooth_manager`
  - 处理目标蓝牙设备检测
  - 输出稳定的设备在线/离线状态

- `motion_controller`
  - 处理平台运动命令
  - 统一封装前进、回零、停止、急停等动作

- `state_machine`
  - 处理系统主状态切换
  - 管理开机、关机、异常与手动模式逻辑

- `safety_manager`
  - 处理超时、越界、限位异常、未到位异常

- `ui_feedback`
  - 处理串口日志、LED 状态、蜂鸣器提示

- `config_store`
  - 统一管理位置参数、超时参数、滤波参数等

## 4. 推荐状态机

建议使用以下主状态：

- `IDLE_CLOSED`
- `HOMING`
- `OPENING_AND_EXTENDING`
- `IDLE_OPEN`
- `RETRACTING_AND_CLOSING`
- `ERROR_STATE`
- `MANUAL_MODE`

### 状态说明
- `IDLE_CLOSED`：待机闭合状态
- `HOMING`：上电回零或重新校准
- `OPENING_AND_EXTENDING`：平台前进、滑盖同步打开
- `IDLE_OPEN`：到达工作位后的保持状态
- `RETRACTING_AND_CLOSING`：平台回位、滑盖同步关闭
- `ERROR_STATE`：异常停机状态
- `MANUAL_MODE`：手动调试状态

### 4.1 推荐状态切换关系
```text
上电
  ↓
HOMING
  ↓
IDLE_CLOSED
  ├─(蓝牙稳定在线)────► OPENING_AND_EXTENDING ───► IDLE_OPEN
  │
  └─(手动模式请求)────► MANUAL_MODE

IDLE_OPEN
  ├─(蓝牙稳定离线)────► RETRACTING_AND_CLOSING ───► IDLE_CLOSED
  │
  └─(手动模式请求)────► MANUAL_MODE

任意状态
  ├─(故障/越界/超时)──► ERROR_STATE
  └─(维护恢复)────────► HOMING 或 MANUAL_MODE
```

### 4.2 状态切换原则
- 蓝牙状态变化不应直接触发动作，建议先经过稳定时间确认。
- 平台未完成回零前，不进入自动运行状态。
- 出现超时、限位异常或未到位时，应立即进入 `ERROR_STATE`。
- `MANUAL_MODE` 应具备最高操作优先级，用于调试和维修。

## 5. 建议输入输出接口

### 输入信号
- 蓝牙状态输入
- 原点开关输入
- 终点保护开关输入
- 急停输入（建议预留）
- 手动模式按键（建议预留）
- 手动前进 / 后退按键（建议预留）

### 输出信号
- 驱动器控制输出
- 状态指示灯输出
- 蜂鸣器输出
- 串口调试输出
- 维护模式状态输出（可选）

### 5.1 推荐 I/O 角色分配思路
建议按“功能分组”而非单纯按空闲引脚来规划 I/O：

- 一组 GPIO 专门用于运动控制
- 一组 GPIO 用于开关量输入
- 一组 GPIO 用于人机交互与指示
- 一组保留给后续扩展（如 OLED、按键、远程控制）

这样更有利于后续维护和版本演进。

## 6. 软件保护建议

建议加入以下保护机制：

- 回零超时保护
- 平台动作超时保护
- 平台未到位保护
- 限位触发异常保护
- 蓝牙信号抖动过滤
- 状态切换去抖与延时确认
- 手动模式退出确认
- 断电重启状态恢复检查

### 6.1 推荐故障分类
建议将故障按类型管理：

- `FAULT_HOME_TIMEOUT`
- `FAULT_OPEN_TIMEOUT`
- `FAULT_CLOSE_TIMEOUT`
- `FAULT_LIMIT_TRIGGERED`
- `FAULT_POSITION_NOT_REACHED`
- `FAULT_BLUETOOTH_UNSTABLE`
- `FAULT_MANUAL_ABORT`

### 6.2 推荐故障处理原则
- 立即停止平台输出
- 记录故障代码
- 输出串口调试日志
- 用 LED / 蜂鸣器提示当前异常状态
- 仅允许用户通过人工确认、手动模式或重新回零恢复

## 8. 推荐主循环设计

建议采用**非阻塞式主循环 + 状态机调度**，避免使用长时间阻塞 `delay()` 或不可中断的 `while` 流程。

### 8.1 主循环职责建议
主循环应持续完成以下任务：
- 采集输入状态
- 更新蓝牙稳定状态
- 更新限位与故障状态
- 执行状态机
- 更新输出状态
- 记录日志与调试信息

### 8.2 推荐主循环伪代码
```cpp
void loop() {
  readInputs();
  updateBluetoothState();
  updateSafetyState();
  runStateMachine();
  updateOutputs();
  publishLogs();
}
```

### 8.3 设计原则
- 所有动作应拆分为“开始动作”和“等待完成”两个阶段。
- 任意循环周期都应能够响应急停、限位和故障状态。
- 所有超时判断都应基于 `millis()` 而不是阻塞等待。

## 9. 运动控制接口建议

建议统一抽象运动控制接口，避免状态机直接操作底层驱动细节。

### 9.1 推荐接口示例
```cpp
void motionMoveTo(long target);
void motionStop();
void motionEmergencyStop();
bool motionAtTarget(long target, int tolerance);
long motionGetPosition();
bool motionIsBusy();
```

### 9.2 接口设计原则
- 状态机只下发目标，不处理具体驱动脉冲细节。
- 驱动细节集中在 `motion_controller` 模块内部。
- 若后续驱动器型号变化，尽量只改执行层，不改状态机逻辑。

## 10. 蓝牙检测逻辑建议

### 10.1 蓝牙状态判断建议
蓝牙状态不建议使用“瞬时检测结果”直接驱动动作，应使用稳定判断：
- 连续检测到目标设备在线一段时间后，才认定为“已开机”
- 连续检测不到目标设备一段时间后，才认定为“已关机”

### 10.2 推荐判断要点
- 绑定目标设备 MAC 地址
- 增加稳定时间窗口
- 增加状态切换最小保持时间
- 对异常抖动做忽略处理

### 10.3 推荐输出结果
蓝牙模块最终只向状态机输出：
- `DEVICE_ONLINE`
- `DEVICE_OFFLINE`
- `DEVICE_UNCERTAIN`

这样可以减少状态机复杂度。

## 11. 调试建议

调试顺序建议如下：

1. 验证原点开关状态
2. 验证平台位置读取
3. 验证回零逻辑
4. 验证单次前进和回位动作
5. 验证蓝牙触发逻辑
6. 验证故障保护逻辑
7. 最后验证与滑盖联动的整体动作

### 11.1 推荐分阶段调试方法
#### 第一阶段：静态输入验证
- 检查原点、限位、按键输入是否正确。
- 检查蓝牙状态是否稳定。
- 检查串口输出是否符合预期。

#### 第二阶段：单轴运动验证
- 在无外部层板与饰面干涉条件下测试平台前进与回位。
- 校准回零位置和工作位置。
- 检查动作时间是否在预期范围内。

#### 第三阶段：联动验证
- 检查平台滑出时前滑盖是否同步后收。
- 检查关闭状态下的顶面拼缝与终点定位。
- 检查联动过程中是否存在异响、卡滞或偏摆。

#### 第四阶段：整机联调
- 验证蓝牙触发完整流程。
- 验证异常状态进入与恢复流程。
- 验证断电重启后的系统行为。

### 12.1 模块设计原则
- 每个模块只负责单一职责。

- 所有关键参数集中在配置模块。
- 故障处理逻辑应统一，不要散落在多个流程分支中。

## 13. 日志与调试输出建议

建议定义统一日志等级：
- `INFO`
- `WARN`
- `ERROR`
- `DEBUG`

### 13.1 推荐日志内容
- 蓝牙状态变化
- 状态机切换记录
- 回零开始 / 结束
- 平台前进 / 回位开始和结束
- 故障发生时间与故障代码
- 手动模式进入与退出

### 13.2 日志输出建议
- 开发阶段优先使用串口输出。
- 若后续增加 Web 配置页，可扩展为网页日志查看。
- 若增加 OLED，可将当前状态和故障码显示在屏幕上。

## 14. 手动模式设计建议

建议在调试和维护阶段支持 `MANUAL_MODE`：

### 14.1 手动模式功能
- 手动前进
- 手动后退
- 停止动作
- 读取当前位置
- 执行回零
- 清除故障

### 14.2 手动模式注意事项
- 手动模式应禁止蓝牙自动逻辑抢占。
- 手动模式应限制最大速度，降低误操作风险。
- 手动模式退出后建议重新回零或重新确认当前位置。
